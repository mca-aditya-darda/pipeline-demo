Reflected XSS (Cross-Site Scripting)

Reflected XSS occurs when an application receives input in an HTTP request and includes that data within the immediate response in an unsafe way, without proper sanitization or encoding.

💡 Exploit Payload Hints
Try inputs containing script commands or handler attributes:
<img src=x onerror=alert(document.cookie)>
<script>alert('Hello!')</script>
Client Display Output

Code Comparison

Comparing how parameters are handled inside the Express endpoint router.

🚨 Vulnerable Code (Express)
app.get('/api/xss/vuln', (req, res) => {
  const name = req.query.name || 'Guest';
  // Send HTML back directly containing the unescaped query parameter
  res.send(`<span>Hello, ${name}! Welcome back.</span>`);
});
🛡️ Secure Code (HTML Escaping)
app.get('/api/xss/secure', (req, res) => {
  const name = req.query.name || 'Guest';
  // Replace HTML special characters with safe entity encodings
  const escapedName = name
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .replace(/"/g, "&quot;")
    .replace(/'/g, "&#039;");
  res.send(`<span>Hello, ${escapedName}! Welcome back.</span>`);
});

SQL Injection (SQLi)

SQL Injection allows attackers to interfere with queries made to a backend database. Users can execute arbitrary statements that bypass access control logic, access sensitive records, or modify databases.

💡 Exploit Payload Hints
Force the query logic to evaluate to true for all rows:
' OR '1'='1

Or perform a UNION injection to pull records from the internal users credentials schema:
' UNION SELECT username, role, secret_token FROM users --

Code Comparison

Comparing database queries: Concatenating strings vs Parameterized bindings.

🚨 Vulnerable Code (SQLite)
app.get('/api/sqli/vuln', (req, res) => {
  const category = req.query.category || '';
  // Directly appending strings breaks query separation boundaries
  const query = `SELECT name, category, price 
                 FROM products 
                 WHERE category = '${category}'`;

  db.all(query, [], (err, rows) => {
    res.json({ results: rows, query });
  });
});
🛡️ Secure Code (Parameterized Queries)
app.get('/api/sqli/secure', (req, res) => {
  const category = req.query.category || '';
  // Using parameters (?) isolates variables from syntax definitions
  const query = `SELECT name, category, price 
                 FROM products 
                 WHERE category = ?`;

  db.all(query, [category], (err, rows) => {
    res.json({ results: rows, query });
  });
});

Command Injection

Command Injection allows an attacker to execute arbitrary system shell commands on the host operating system. This happens when inputs are passed into system runners (like Node's exec) without validation.

💡 Exploit Payload Hints
Chain a second system command using shell separator operators:
Windows shell: 127.0.0.1 & dir or 127.0.0.1 & type index.js
Unix shell: 127.0.0.1 ; ls -la or 127.0.0.1 ; cat index.js

Code Comparison

Validating input strings before executing command subprocesses.

🚨 Vulnerable Code (Node Child Process)
app.post('/api/cmd/vuln', (req, res) => {
  const ip = req.body.ip || '127.0.0.1';
  // Runs direct string inside OS default shell environment
  const pingCmd = `ping -n 2 ${ip}`;

  exec(pingCmd, (err, stdout, stderr) => {
    res.json({ command: pingCmd, output: stdout || stderr });
  });
});
🛡️ Secure Code (Strict Regex & Shell Isolation)
app.post('/api/cmd/secure', (req, res) => {
  const ip = req.body.ip || '127.0.0.1';
  
  // 1. Strict regex sanitizes allowed characters
  const ipRegex = /^[a-zA-Z0-9.-]+$/;
  if (!ipRegex.test(ip)) {
    return res.json({ output: 'Error: Invalid input.' });
  }

  // 2. Ideal: Avoid shell expansion entirely with execFile
  // Alternative: safe execution of validated string
  const pingCmd = `ping -n 2 ${ip}`;
  exec(pingCmd, (err, stdout, stderr) => {
    res.json({ command: pingCmd, output: stdout || stderr });
  });
});

Code Comparison

Resolving base boundaries to prevent parent relative traversal path mappings.

🚨 Vulnerable Code (FS Reader)
app.get('/api/path/vuln', (req, res) => {
  const filename = req.query.filename || 'system.log';
  // Standard concatenation without path validation checks
  const filepath = path.join(logsDir, filename);

  fs.readFile(filepath, 'utf8', (err, data) => {
    res.json({ filename, content: data, filepath });
  });
});
🛡️ Secure Code (Path Resolution Check)
app.get('/api/path/secure', (req, res) => {
  const filename = req.query.filename || 'system.log';
  
  // 1. Resolve safe absolute paths
  const safeBase = path.resolve(logsDir);
  const candidatePath = path.resolve(path.join(logsDir, filename));
  
  // 2. Reject if final resolved path exits safe boundary
  if (!candidatePath.startsWith(safeBase)) {
    return res.status(403).json({ error: 'Access Denied' });
  }

  fs.readFile(candidatePath, 'utf8', (err, data) => {
    res.json({ filename, content: data });
  });
});
Vulnerable

Dependency Prototype Pollution (lodash)

Prototype Pollution occurs when a library (such as outdated lodash <= 4.17.19) merges user-provided objects into target templates without stripping internal javascript constructor references. Attackers can pollute Object.prototype, injecting malicious parameters globally.

💡 Exploit Payload Hints
Specify "__proto__" properties inside the JSON payload:
{ "__proto__": { "polluted": "PROTOTYPE_POLLUTION_WORKING" } }

This injects the key into every newly instantiated object context on the server runtime.

Code Comparison

Reviewing the recursive merge routines: Vulnerable lodash vs Safe merge routines.

🚨 Vulnerable Code (Outdated Lodash 4.17.19)
app.post('/api/dep/vuln', (req, res) => {
  const parsed = JSON.parse(req.body.payload);
  const targetObj = {};
  
  // Vulnerable merge copies __proto__ properties
  lodash.merge(targetObj, parsed);

  res.json({
    isPolluted: !!({}).polluted,
    targetObject: targetObj
  });
});
🛡️ Secure Code (Key Block Sanitization)
app.post('/api/dep/secure', (req, res) => {
  const parsed = JSON.parse(req.body.payload);
  const targetObj = {};

  // Custom merge routine blocks prototype pollution
  const safeMerge = (target, source) => {
    for (const key in source) {
      if (key === '__proto__' || key === 'constructor') {
        continue; // Block injection path
      }
      if (typeof source[key] === 'object' && source[key] !== null) {
        if (!target[key]) target[key] = {};
        safeMerge(target[key], source[key]);
      } else {
        target[key] = source[key];
      }
    }
  };
  
  safeMerge(targetObj, parsed);
  res.json({
    isPolluted: !!({}).polluted,
    targetObject: targetObj
  });
});
